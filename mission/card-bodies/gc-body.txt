CODE GATE — lane <N>. The driver never commits. Nothing is committed unless a human chooses to commit it.

The driver completes this card only when the newest review verdict is PASS, and records the staged path list in the result. It runs no build of its own — the review cards ran the plan's Run commands, and at a manual gate you run whatever verification you want.

If this lane runs with human gates (the default), the driver pauses here. Your options as the gate-holder:
1. Read the plan at <PLAN> and the newest review verdict — RVa, RVc, or their latest re-review round — with the run evidence in the driver log.
2. Check by hand every success criterion <REFINED> marks `manual at Gc`; no card could automate those.
3. Inspect the staged index: git diff --cached --stat
4. Commit and push if you want this work in history — entirely at your discretion, with an explicit pathspec. The flow does not require it.
5. Complete this card. Write PASS — the driver adds its own evidence line and the staged
   path list beside it, so nothing else needs to be written:
       hermes kanban --board <BOARD> complete <YOUR-CARD-ID> --result "PASS: accepted"
   PASS is the first word and the only one that releases the lane; your own words may
   follow the colon ("PASS: reviewed the diff, committing it").

Complete it from the CLI (the command above), or from a browser on the dashboard — in a
browser the Complete dialog asks for a summary: type PASS (or PASS: <your words>) into it.
The desktop app cannot complete a card at all: its `Complete` collects the summary with
`window.prompt`, which Electron does not implement, so the click does nothing
(DESIGN.md, *Known traps*).

OPTIONAL: the board does not need it — the driver records the evidence line. MANDATORY in the dashboard's Complete dialog, so type PASS there.

Completing this card is what releases the next lane's root card.
